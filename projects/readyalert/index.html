BPSR Ready Alert

Ready/queue alerts plus an optional view-only BPSR chat overlay with filters, English translation and Guild/Party TTS.

Download latest EXE

Latest release: checking…

Use

  1. Make sure Npcap is installed.
  2. Open BPSR Ready Alert.
  3. Select Resonance Logs CN or the correct network adapter if auto-detection misses it.
  4. Leave it running in the system tray.
  5. Enable Chat Overlay only if you want the chat window, translation or TTS.

What it does

  • Matchmaking / Ready Check sound alerts and optional desktop notifications.
  • Optional chat overlay with World, Guild/Team, All and custom tabs.
  • Filters, keyword sounds, opacity, click-through, Always on Top and smoother follow-latest scrolling.
  • Optional English translation for World, Guild and Party / Team chat.
  • Optional English TTS for Guild and Party / Team only. World chat is never spoken.
  • Alerts + chat share one Npcap capture pipeline.

Audio controls

ReadyAlert keeps its three audio volumes separate so one feature cannot accidentally change another:

  • Ready / Queue volume — matchmaking and Ready Check alerts.
  • Chat alert volume — keyword and Private/Talk sounds.
  • TTS volume — spoken Guild / Party chat only.

The TTS toolbar also shows its state clearly: green = active, red = off, amber = enabled but muted or no speech channel is selected.

v1.2.1 reliability changes

  • Settings clearly show Saved, Unsaved, or Applied — not saved states.
  • Blocked players are suppressed from overlay rows, chat sounds, translation and not-yet-playing TTS.
  • Npcap adapter switching preflights the new adapter and rolls back if the switch fails.
  • Large chat bursts use bounded UI work so the overlay stays responsive.
  • Clipboard and diagnostics interactions are hardened against common Windows UI errors.

Notes

Npcap is required and is not bundled. ReadyAlert can run beside Resonance Logs CN and can auto-launch it.

ReadyAlert does not inject into BPSR, replace game files, send chat, or automate gameplay.

Translation/TTS use no-key Google Translate/gTTS-style web endpoints. They can be rate-limited or changed upstream; failures do not stop normal Ready/Queue alerts or local chat capture.
